# Stage 1 — Core & Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running, tested backend: monorepo, pure business rules, Postgres schema with RLS, passwordless auth (email code + magic link, passkeys, OAuth server), the `/v1` API, and the Budge CSV importer, all runnable with `docker compose up`.

**Architecture:** pnpm + Turborepo monorepo. `packages/core` holds pure functions and zod schemas; `packages/db` holds the Drizzle schema, migrations and a `withUser` helper that sets the RLS context; `packages/importers` parses Budge CSVs; `apps/api` is a Hono app (`@hono/zod-openapi`) that wires Better Auth and the routes. Packages export TypeScript source directly (no build step); apps run with `tsx`.

**Tech Stack:** Node 22, pnpm 12, Turborepo 2, TypeScript 7, Biome 2, Vitest 5, zod 4, Hono 4 + `@hono/zod-openapi` 1 + `@hono/node-server`, Drizzle ORM 0.45 + drizzle-kit 0.31 + `postgres` (postgres-js) 3, Postgres 17, Better Auth 1.7 (+ `@better-auth/passkey`, `@better-auth/oauth-provider`), `uuidv7`, `csv-parse`, `nodemailer` (local SMTP to Mailpit), `resend`, `@testcontainers/postgresql`.

**Spec:** `docs/superpowers/specs/2026-10-20-lukas-design.md`

## Global Constraints

- Everything in the repo is English: code, comments, docs, commit messages (Conventional Commits). User-facing copy ships in `es` and `en`.
- Money is an integer number of minor units (cents) in JS `number` and Postgres `bigint` (`mode: "number"`). Never floats. Amounts are signed: expense < 0, income > 0, never 0.
- Months are `"YYYY-MM"` strings (`Month`); dates are `"YYYY-MM-DD"` strings (`IsoDate`), stored as Postgres `date`.
- Domain ids are UUID v7 (`uuidv7()`); Better Auth's `user.id` is `text` and domain `user_id` columns are `text` referencing it with `ON DELETE CASCADE`.
- Every domain table has `user_id`, RLS enabled **and forced**, policy `user_id = current_setting('app.user_id', true)`. The API connects as the non-superuser role `lukas_app`; migrations run as the admin role.
- No route queries domain tables outside `withUser(db, userId, fn)`.
- Errors are `application/problem+json` `{ type, title, status, code, detail?, errors? }`.
- Default account: name `"Main"`, currency `"EUR"`.
- Auth codes: 6 digits, valid 600 s, single use, max 3 attempts. Magic link: `{WEB_URL}/auth/verify?email=<email>&code=<code>`.
- OAuth scopes: `finance:read`, `finance:write`.
- Summary state thresholds: `near` when spent/budget ≥ 0.8, `over` when > 1.0.
- The author's real Budge CSV never enters the repo; fixtures are invented.
- Never add Claude as co-author in commits.

## Review Focus

1. **Time-zone month boundary:** at 2026-11-01T03:00Z a user in `America/Bogota` is still in October; `GET /v1/summary` with no month must return `2026-10`. → test in Task 2 (`todayIn`) and Task 12.
2. **Edited recurrence occurrence:** if the user changes the amount of this month's generated Spotify, the next summary call must not reset or duplicate it. → test in Task 12.
3. **Archived category with spending:** archiving a category mid-month must not make its spending disappear from "remaining". → test in Task 12.
4. **Idempotency key reused with a different body:** must be rejected with 422 `idempotency_key_reused`, not silently return the old transaction. → test in Task 11.
5. **Pagination over many same-day transactions:** 120 transactions on one date paginated by 50 must return each exactly once. → test in Task 11.

- Consumes: `Month` (Task 2)
- Produces:
  - `type CategoryKind = "expense" | "income"`; `type TxStatus = "paid" | "pending"`
  - `interface BudgetEntry { categoryId: string; amount: number; effectiveFrom: Month }`
  - `effectiveBudget(entries: BudgetEntry[], categoryId: string, month: Month): number | null`
  - `interface SummaryInput { month: Month; categories: { id: string; kind: CategoryKind }[]; budgets: BudgetEntry[]; transactions: { categoryId: string; amount: number }[] }`. The caller passes only that month's non-deleted transactions (paid and pending).
  - `interface CategorySummary { categoryId: string; budget: number | null; spent: number; remaining: number | null; ratio: number | null; state: "ok" | "near" | "over" }`
  - `interface MonthSummary { month: Month; budgetTotal: number; spent: number; remaining: number; income: number; balance: number; categories: CategorySummary[] }`. `categories` contains **expense categories only**, in input order.

Per category: `remaining = budget − spent` and `ratio = spent / budget` when budget > 0; budget null → `remaining`/`ratio` null, state `ok`; budget 0 → ratio null, state `over` if spent > 0, else `ok`.

### Task 7: Budge CSV importer (`@lukas/importers`)

**Files:**
- Create: `packages/importers/package.json` (dependency `csv-parse`), `src/index.ts`, `src/budge/parse.ts`, `src/budge/derive.ts`, `src/category-style.ts`
- Create: `packages/importers/test/fixtures/budge-sample.csv` (invented data)
- Test: `packages/importers/test/budge.test.ts`, `packages/importers/test/category-style.test.ts`

**Interfaces:**
- Consumes: `parseDecimalToMinor`, `IsoDate`, `Month`, `CategoryKind` from `@lukas/core`
- Produces:
  - `interface BudgeRow { line: number; date: IsoDate; name: string; amount: number; currency: string; category: string; note: string | null; status: "paid" | "pending" }`
  - `parseBudgeCsv(text: string): { rows: BudgeRow[]; rejected: { line: number; reason: "invalid_date" | "invalid_amount" | "zero_amount" | "missing_category" }[] }`. Throws `UnrecognizedFormatError` when no transactions header block is found.
  - `inferCategoryKinds(rows: BudgeRow[]): Map<string, CategoryKind>`, keyed by `normalizeName(category)`; majority sign by count; ties → `expense`
  - `normalizeName(s: string): string`: trim, lowercase, strip diacritics
  - `rowHashes(rows: BudgeRow[]): string[]`, parallel to `rows`: `sha256(date|name|amount|normalizeName(category)|ordinal)` hex, where `ordinal` counts earlier identical (date, name, amount, category) rows
