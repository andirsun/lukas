# Stage 2 — Web (landing + app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bilingual (es/en), phone-first web app and a prerendered landing page on top of the Stage 1 API, so the author can replace Budge.

**Architecture:** `apps/web` is a React Router 8 framework-mode app with `ssr: false` and `prerender: ["/", "/en"]`: the landing pages are static HTML, everything under `/app` is a client SPA. It talks to the API through a same-site `/api` path (Vite proxy in dev), with Better Auth's React client for sessions, a typed `openapi-fetch` client generated from `/openapi.json`, and TanStack Query with optimistic updates. Design tokens are generated from `docs/design/system/project/tokens.json`; components follow `docs/design/system/project/components/bundle.css` and live in Storybook. Small backend additions (onboarding flag, name suggestions, cost of living) and the rule-based Lukas messages (pure, in `@lukas/core`) come first.

**Tech Stack:** React 19.3, React Router 8.5 (`@react-router/dev`), Vite 8, TypeScript 7, Tailwind CSS 4 (`@tailwindcss/vite`), Motion 14, TanStack Query 5, `openapi-typescript` 7 + `openapi-fetch` 0.17, `better-auth` 1.7 React client (+ `@better-auth/passkey/client`), `use-intl` 4 (ICU messages), Recharts 3, three 0.186 + `@react-three/fiber` 9 + `@react-three/drei` 10, `@fontsource/fredoka` + `@fontsource/nunito`, Storybook 10 (`@storybook/react-vite`, `@storybook/addon-vitest`, `@storybook/addon-a11y`), Vitest 5 (browser mode with `@vitest/browser-playwright`), Playwright 1.64 + `@axe-core/playwright`.

**Spec:** `docs/superpowers/specs/2026-10-21-stage-2-web-design.md` (builds on `docs/superpowers/specs/2026-10-20-lukas-design.md`). Design system: `docs/design/system/`. Mockups: `docs/design/stage-2-mockups/`.

## Global Constraints

- Everything in the repo is English (code, comments, commits); routes are English; UI copy ships in `es` (default) and `en` — no hardcoded user-facing strings in components.
- React Router **8** (the spec says 7; 8 is the current major with the same `ssr: false` + `prerender` framework mode).
- No PWA: no manifest, no service worker.
- Money stays integer cents end to end; parsing and formatting go through `@lukas/core` (`parseDecimalToMinor`, `formatMinorAsDecimal`) and `Intl.NumberFormat`. Never floats.
- Every color, radius, spacing, shadow and duration in web code comes from the generated tokens (CSS variables); no literal colors in components (the phone bezel in stories excepted).
- Every pressable element has a solid bottom edge that collapses on press, a visible `:focus-visible` ring in `--focus`, and a 44px minimum touch target.
- Status (`ok`/`near`/`over`) is always paired with words, never color alone.
- The home month defaults to the **user's profile time zone** (from `GET /v1/me`), never the browser's.
- `POST /v1/transactions` always sends an `Idempotency-Key` that is stable for one open add sheet.
- `prefers-reduced-motion`: fades only; `Lukas3D` replaced by a still image.
- API base path for the browser is `/api` (dev: Vite proxy strips `/api` and forwards to `http://localhost:3000`). The API's `API_URL` is the browser-facing URL (`http://localhost:5173/api` in dev) so Better Auth cookies are first-party.
- Never add Claude as co-author in commits.

## Review Focus

2. **Optimistic save that fails:** the hero amount and the list roll back and an error toast appears. → test in Task 12.

5. **Theme flash:** a user who forced `day` on a night-mode OS never sees a night frame on load (theme applied before first paint). → test in Task 6.

### Task 4: Rule-based Lukas messages (core)

**Files:**
- Create: `packages/core/src/lukas-message.ts`; Test: `packages/core/test/lukas-message.test.ts`

**Interfaces:**
- Consumes: `MonthSummary` (Stage 1), `IsoDate`, `lastDay`, `monthOf`.
- Produces:
  - `type LukasMessageKey = "first_of_day" | "on_track" | "near_limit" | "over_budget" | "income_received" | "pending_paid" | "month_last_day" | "month_closed_green"`
  - `lukasMessage(input: { summary: MonthSummary; today: IsoDate; todayCount: number; event?: { kind: "saved" | "paid"; categoryId: string; amount: number } }): { key: LukasMessageKey; params: Record<string, string | number> }`

Rules, first match wins:

| # | Condition | Key | Params |
|---|---|---|---|
| 1 | `event.kind === "paid"` | `pending_paid` | `{ amount }` (absolute cents) |
| 2 | `event.kind === "saved"` and `event.amount > 0` and category is not in `summary.categories` (income) | `income_received` | `{ amount }` |
| 3 | `event` and its category state is `over` | `over_budget` | `{ categoryId, over: -remaining }` |
| 4 | `event` and its category state is `near` | `near_limit` | `{ categoryId, remaining }` |
| 5 | `event` and `todayCount === 1` | `first_of_day` | `{}` |
| 6 | `summary.month < monthOf(today)` and `summary.remaining >= 0` | `month_closed_green` | `{ remaining }` |
| 7 | `today === lastDay(summary.month)` | `month_last_day` | `{ remaining }` |
| 8 | no event and any category `over` | `over_budget` | worst category by overspend |
| 9 | no event and any category `near` | `near_limit` | the one with the least remaining |
| 10 | otherwise | `on_track` | `{ remaining, daysLeft }` (days from `today` to `lastDay`, inclusive) |

- [ ] **Step 1: Failing tests:** one test per row using the October 2026 fixture (`packages/core/test/fixtures/october-2026.ts`), e.g. saving −500 in Supermercado → `over_budget` with `over: 1912`; no event on 2026-10-21 → `over_budget` for Supermercado (row 8 beats `on_track`); a summary where all are ok on 2026-10-21 → `on_track` with `daysLeft: 11`; `summary.month "2026-09"`, today 2026-10-01, remaining 100 → `month_closed_green`.
